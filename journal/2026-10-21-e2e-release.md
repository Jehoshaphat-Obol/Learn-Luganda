# 2026-10-21: End-to-end tests, QA and v1.0

Issue: #26 · Branch: `feat/26-e2e-release`

## Done

- **Playwright end-to-end tests** (`e2e/`, `playwright.config.js`). They run
  against the production build from `vite preview` on a desktop Chrome
  profile and a Pixel 7 mobile profile, 40 tests in all:
  - onboarding from the landing page to the path;
  - a full lesson answered perfectly, which earns XP, gems and a streak;
  - running out of hearts, which pauses the lesson;
  - a lesson the day after, which extends the streak;
  - a review session in the practice hub, which earns a heart back;
  - exporting progress, clearing it and importing it again;
  - axe-core on the landing page and 11 app screens, with no violations;
  - an offline lesson after the first visit, through the service worker;
  - the manifest and its icons load.
- To support these, lessons accept `?seed=` so the tests can predict the
  exercises with the same generator and answer them correctly. Match
  exercises are answered by their shared word ids.
- **CI** now runs the e2e suite after the build (installing Chromium) and
  uploads traces on failure. Deploys to Pages only happen after everything
  passes.
- **README** rewritten with a feature list, screenshots
  (`docs/screenshots/`), the development commands and the project layout.
- Version 1.0.0 in `package.json`, with a `v1.0.0` tag after merge.

## QA notes

- Cross-browser coverage is Chromium desktop and Chromium mobile emulation.
  Firefox and Safari aren't in CI yet. The app avoids engine-specific APIs
  and degrades gracefully: no Web Audio means no sound, no Notification API
  means no reminder switch, and no `beforeinstallprompt` means no install
  button.
- Performance: the app is about 55 kB of gzipped JS (course content included) and 11 kB of gzipped
  CSS. There are no images apart from the PWA icons, because the
  illustrations are inline SVG. Fonts load from Google Fonts with
  `display=swap`, and the service worker caches them.

## Follow-up: flaky Continue loop

The first push to main failed e2e: the lesson test clicked "Continue" in a
`while (count())` loop, and under CI load it could grab the last reward
screen's button mid-animation, lose it to the navigation, then wait 30s for a
button that never came back. The app itself had reached the path. The loop is
now `continueToPath()` in `e2e/helpers.js`, which retries each step with
`expect().toPass()`. Verified with the full suite three times over in CI mode
with retries off (120/120).
